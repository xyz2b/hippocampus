# Brief：M1 第 4 项 — 可见性与最小并发（解除 MCP 全局锁对模型调用的占用）

日期 2026-10-04，HEAD `fd7bffe`。用户 2026-10-04 同意开始。

## 背景
写入新路径（write_pipeline=w4_runtime_v1）与召回新路径（recall_pipeline=recall_v3）的离线与 CLI 部分已完成。MCP 服务（src/bin/pmr-mcp.rs）在整次调用期间持有服务全局锁（pmr-mcp.rs:67、:182），模型调用也在锁内，因此：
- 写入新路径在 MCP 上只允许 off/deferred，inline 启动即报错（J6）；
- 召回新路径在 MCP 在线调用时明确报错（W8）。

## 目标（target-design 2.5、2.6）
1. 模型调用（W1/W3/W4 后台、R1/R4 前台）不得在服务全局锁内进行；前台读取快照与后台提交只在必要的短临界区协调。
2. 后台整理任务可恢复且不重复执行：持久化在原文记录，按租约与预算认领；重启后恢复未完成任务；相对时间用接收时间；提交沿用快照、顺序屏障与删除检查（多数已在第 ②③ 段具备，需在 MCP 进程内接通后台执行）。
3. MCP 在线可用：写入新路径的 inline/后台模式、召回新路径的在线 R1/R4 解除报错。
4. **最小并发检查**（2.5）：用受控延迟的模型响应让一个后台任务保持未完成，同时发起前台召回；前台必须在释放后台响应之前完成，并通过 2.6 的新信息可见性检查。
5. **2.6 可见性验收**至少覆盖：旧记录“住上海”、本轮“已搬到南京”时原文立即可用且不给确定的上海当前值；本轮仅假设搬家时不误更新；后台失败、相关新原文被截断、两条更新乱序完成、处理跨日、来源删除时状态都正确呈现。

## 产品约束
- 默认路径（legacy）行为与输出不变。
- 不真实调用模型；用受控延迟的 mock。
- 删除与授权检查不放松；晚到结果不得恢复已删除内容。
- 数据库升版、冻结契约变更、默认切换需用户批准。
- P95 延迟的完整负载验收不在本项（target-design：基线后进行）；本项只做最小并发检查。

## M1.5 真实使用修复（2026-10-06，依据 AF36–AF39）
目标：让“带孩子出行”这类真实对话能被正确记住并跨会话召回，原话无需重说。
范围：P0 宿主路由（工具描述 + ChatGPT 指令：bootstrap 后继续处理同一消息、个人陈述用 prepare 保存、具体问题另调 recall、不擅自 offline=true）；P0 来源状态查看 + 主体确认 + 未提交候选重建；P0 计划记忆（speech=plan 可提交，召回标注为计划，预订事实单列，修改/取消由模型判断更新）；P1 W1/W3 限定语遗漏修正；P1 历史原话补录；P2 W1 low 对照。
不做：自动受限实体、prepare 只读模式、用用户私有原话发送模型。
验收：去标识 MVP（4 条消息 + 2 次跨会话查询，≤24 次真实调用）——原话可追溯、限定语完整、计划明确标注、无需重说、删除后不能恢复；全套 0 失败；59/4 历史核验不变。
