# Claude 分析与方案草案（AF170，待 Codex 复核）：第③步 混合检索

## 依据
- target-design：R2 = 代码 + 向量；嵌入角色（表 2.x）：输入原文分段、整理文本与查询文本，输出向量；机械校验维度、数值有效性、来源与索引版本；失败退回全文与结构化检索并标注降级；写入/重建按批、普通查询需查询向量；向量调用单独计量。原文删除后向量投影失效；向量记录带来源与模型/索引版本，过期投影不得当作当前数据。第一阶段排除向量，因需引入本地向量模型（roadmap 建议本地 bge-m3）。
- 现状（src/recall.rs R2，src/lexical.rs）：先按授权范围/主体过滤；R1 关系只是提示（不可靠时撤销）；范围 ≤ budget.records 时实际穷举；否则 FTS（cjk-position-v1，字位置 + 已登记别名，无同义）+ phrase_score 字面匹配取候选。未完成整理的原文另走词法检索。
- 缺口：范围大于预算、且问题与记忆没有字面重合时（同义/改写/上位词，如“喝什么饮料”vs“咖啡”、“在哪上班”vs“就职于字节”、跨语言），候选会漏；未整理原文同样只能字面命中。目前没有量化这一缺口的检索评测。

## 原则（不改变的边界）
1. 向量只是候选提示，与 FTS 同级：先过授权/任务/主体范围，再在范围内做相似度；绝不扩大访问范围，绝不作为“完整”的依据，不认证语义（语义仍由 R4 判断）。
2. 小范围穷举路径不变；向量只影响“范围 > 预算”的候选选择与未整理原文的候选。
3. 本轮来源仍按来源 ID 直接进入证据，不依赖向量完成。
4. 嵌入失败/未完成：退回 FTS，召回输出标注降级（vector_unavailable / vector_pending），不当作“无记录”。

## 方案
A. 嵌入提供方（可配置，复用 provider 抽象的最小部分）：OpenAI 兼容 /v1/embeddings 一个协议即可覆盖 Ollama（本地）、DashScope（qwen3.7-text-embedding）与 OpenAI 代理。配置写模型、维度、环境变量名；模型 ID 与维度进入索引版本。
   默认建议本地（Ollama bge-m3 或 qwen3-embedding 系列）：嵌入覆盖用户全部原文（含私密聊天），本地不外发，零费用；用户此前不授权私有原文再发给模型。云端只作评测对照，且只用公开/合成样本。
B. 存储：SQLite 新表 vectors(owner, kind=source_segment|memory, ref_id, segment, model_version, dims, blob f32, source_revision)；暴力余弦（个人规模 ≤ 数万条，毫秒级）。ponytail：暴力扫描，规模 >10 万再换 sqlite-vec/ANN。来源删除/重提取级联失效；版本不符不参与检索；重建按批。
C. 写入：W0 不同步嵌入（不拖慢前台）；后台整理队列中对新原文分段（复用 lexical::segments）与提交的记忆文本（value + 证据引用）按批嵌入；记录 usage/耗时，单独计量。
D. 召回：查询文本（问题 + 上下文 + R1 关系/条件提示，与现 hint 同源）嵌入 1 次；在已授权候选集合内取向量 top-k，与 FTS 命中、phrase_score 做 RRF 融合；融合后仍受 budget.records 限制，截断如实报告。未整理原文同样融合。查询嵌入失败 → 只用 FTS 并标注。
E. 不做（本轮）：rerank 模型（DashScope 有 qwen3.7-text-rerank，待测出需要再加）、ANN 索引、按向量判同槽/冲突（W4 仍按现规则）。

## 评测（先量化再上线）
1. 新建检索评测（零生成式调用）：固定的合成记忆库（中文为主，规模大于 budget.records，以触发非穷举路径）+ 约 30 条查询，覆盖同义/改写/上位词/跨语言/否定/时间等；人工标注每条查询的相关记录与原文。指标：recall@k（k=budget.records）、漏召回列表、延迟。样本由 Claude 起草、用户抽检。
2. 对照：FTS-only（现状） vs 混合（2–3 个本地嵌入候选：bge-m3、qwen3-embedding 0.6B/4B；可选 DashScope qwen3.7-text-embedding 作云端对照，仅合成样本，需授权与费用估算）。
3. 回归：现有 recall/R4 评测回放不变（小范围穷举路径不受影响）；之后第④步召回侧阶段对比在混合检索上进行。

## 请 Codex 复核
- 缺口判断是否成立（是否有更便宜的替代，如别名/同义扩展足够）；向量在 R2 的位置与边界是否与契约（recall.v6、completeness 报告）一致，需不需要契约升版（新增降级原因字段）。
- 嵌入写入时机（后台队列）与删除/重建/版本失效的最小实现；是否复用 lexical 的同步/回执机制。
- 存储与暴力检索是否足够；RRF 参数与 budget 交互。
- 检索评测设计、本地嵌入候选与机器资源（M4 32GB，同时有 27B 模型时内存）。
- 最小范围、分步与允许修改文件；预计的真实调用（本地嵌入无费用，但需用户确认安装模型）。
