# 记忆能力现状

> 历史文档：下文保留原版本的实现描述、命令及结论，不是当前执行入口。旧写入及 legacy/local/assisted 召回已退出；当前路径、配置、备份与评测见 [架构索引](README.md)。0517000 仅作参考，不是上线门槛。

本文按 LongMemEval 的五个评测维度，梳理当前代码中的实现方式和短板，对应提交 `a2d3b96`。仓库中的评测脚本位于 `examples/longmemeval_*`。

总体结论：**信息抽取、知识更新、弃答做得比较深；时间推理只覆盖一部分；多会话推理基本没有实现。**

| 能力 | 成熟度 | 主要机制 | 最大短板 |
| --- | --- | --- | --- |
| 信息抽取 | 高 | 模型提取、独立核验、本地原文与时间落地校验 | 谓词目录小，大量内容落到整句 `fact` 槽；不从助手回复中提取 |
| 多会话推理 | **低** | 只有二元比较，以及“值必须唯一”的单值问答 | 没有跨会话聚合、计数、多跳推理，全部交给宿主模型 |
| 知识更新 | 高 | 语义槽、版本链、更新意图、冲突不选边、更正与未整理原文拦截 | 依赖模型判断更新意图，误判时只会得到 Conflict |
| 时间推理 | 中 | 多种时间分开记录、确定性换算、历史查询、“搬到某地之前”边界 | 没有时间计算、事件排序、时长推理；时间问题只做字面匹配 |
| 弃答 | 高（偏保守） | 写入、召回、答案契约三层拒答 | 过度拒答，放行句式窄；默认 legacy 模式无法核准任何答案 |

## 1. 信息抽取

**当前做法**：两次模型调用，加上本地逐层校验。详见 [write-path.md](write-path.md) 第 6 节。

1. **提取**（`OpenAiMemoryExtractor::extract_turn`，`src/openai.rs:1561`）：模型输入包括当前用户原话、必要的历史用户消息，以及实体、谓词、领域目录。输出受严格 JSON Schema 约束，实体 ID、谓词、领域都只能从目录中选。每条原子候选包含：
   - 主体、类型（Fact / Preference / Constraint / Episode）、谓词、值、正负方向、适用条件（Scope）；
   - 时间表达式、留存层级、提取置信度、用户确定度、来源类别、更新意图。
2. **本地解码**（`decode_extraction_with_feedback`）：证据字段由运行时注入，模型不能生成。通用 `fact` 槽的值必须是原文中一个完整的用户句子。日期由本地换算，并要求与模型给出的日期一致。
3. **独立核验**：另一次模型调用，对每个候选逐项判断 9 个维度（主体、关系、值、方向、条件、时间、意图、来源、元数据），同时判断当前消息里应记住的断言是否都已提取。
4. **本地复核**（`verify_source_support`，`src/openai.rs:1315`）：核验中引用的原文片段必须真实存在；时间信息必须能在原文中与同一个断言对上（`src/temporal_grounding.rs`）。全部通过后才签发核验快照。覆盖不全时整批失败，不会只提交一部分。
5. **可选修复**：出现可定位的错误或遗漏时，重新提取一次（需要预算显式授权，单次操作最多 4 次模型调用）。

**局限**：

- 谓词目录很小，默认只有十几个；目录之外的内容都落到通用 `fact` 槽，值就是整句原文，本质上是原文存档，不是结构化知识。
- 只从用户的话里提取，助手的回答一律不入库。
- 证据引用保存的是整条消息，没有精确到事实所在的那一小段文字。

## 2. 多会话推理

指跨会话的聚合、计数、汇总和多跳推理。

**当前做法**：几乎没有真正的推理，只有两处有限的支持。

- **比较**：“X 的 A 和 B 是否一致”这类问题，要求两个关系各自找到精确链接到原文的证据（`compared_properties`，`src/local_recall.rs`）。assisted 模式可以让模型提议“问题里的关系对应哪条事实”，但最终结论不核准，状态为 `comparison_conclusion_not_verified`。
- **单值问答**：“X 的 Y 是什么/多少”，要求该值在整个快照中唯一。多条记录值不同时直接拒答，不做合并。

**没有的能力**：

- 跨会话的计数、求和、列举，例如“我一共去过几个国家”“这个月买了哪些东西”；
- 从多条经历（Episode）归纳出偏好；
- 多跳推理，例如“我女儿的老师住在哪”。

召回会把多条相关记忆和原文片段一起返回，但**推理全部交给宿主模型完成**，而宿主模型写出的答案，系统不会核准。`src/fact_answer.rs` 中的数量问题，只是“每人最多借几本”这类单条规则的字面解析，不是聚合计算。

## 3. 知识更新

这是目前做得最完整的一块，主要在 `src/policy.rs` 和 `src/engine.rs`。详见 [write-path.md](write-path.md) 第 8 节。

- **更新意图由模型判断**：Assert / Refine / Supersede（附原因：状态变化、纠错、偏好变化、约束变化、范围修正）/ Retract / Conflict。
- **规则引擎按“语义槽”执行**：语义槽由主体、类型、谓词决定；多值谓词还要加上值本身。

| 情况 | 处理 |
| --- | --- |
| 普通断言，同槽同条件没有记录 | 新增 |
| 普通断言，同槽已有相同断言 | 强化：计数加一；达到阈值时从短期升为长期 |
| 普通断言，同槽已有不同断言 | **Conflict，不覆盖**。单凭值不同，无法区分是现实变化还是纠错 |
| 明确的替换或细化 | 旧版本标为 Superseded，写入 `valid_to`，与新版本双向链接 |
| 撤回 | 结束旧版本，不生成反向记录 |

- **状态变化的时间切换**：新旧版本共用一个切换时间点，优先用用户给出的日期，否则用说这句话的时间。切换时间与旧版本有效期矛盾时，判为冲突。
- **纠错与现实变化分开处理**：因纠错被替换的旧版本，永远不会出现在历史查询里，因为它从未成立过。
- **召回侧的额外保护**（`src/local_recall.rs:1691`）：
  - 如果有更新的原文含“更正、撤回、改为、不再”等字样，与它相关的旧事实不能作为当前答案；
  - 如果同一主体有尚未整理完的新原文，就返回 `uncommitted_newer_revision`，不放行答案。
- **查询时的冲突**：同槽、同样具体、断言不同的两条记录，两条都不返回，只报告冲突。

**局限**：更新是否发生、是哪种更新，完全依赖模型给出的 `intent`。模型把一次更新误判为普通断言时，结果只会是 Conflict，不会自动更新。

## 4. 时间推理

**当前做法**：时间的“表示”做得很细，“推理”只覆盖有限几类。

**表示**：`Temporal` 把几种时间分开记录（`src/model.rs:329`）：

| 字段 | 含义 |
| --- | --- |
| `observed_at` | 系统何时得知 |
| `valid_from` / `valid_to` | 现实中何时成立（左闭右开） |
| `expires_at` | 系统何时淘汰这条记忆 |
| `reference` | 无法换算成日期的时间，例如“旅行结束后”，或原样保留的未知表达 |

每个时间点还标注来源：Explicit（用户明说）、Inferred（系统推断）、Supersession（由版本切换得出）、Unknown。

**换算**（`src/temporal.rs`）：确定性规则，按配置的时区计算：

- “最近”固定为过去 30 天；
- 今天、明天、昨天、后天；
- “下个月”“去年六月”等换算为完整自然月；
- ISO 日期；
- “每天早上”这类周期表达映射为时段条件，不当作日期。

**落地校验**（`src/temporal_grounding.rs`）：时间信息必须能在原文中与同一个断言对上，否则拒绝，防止模型把其他句子里的日期套到这条事实上。

**查询**（`src/retrieval.rs`）：

- 查当前状态：按查询时间做点查询；
- 查历史：读截至查询时间已成立的版本，只有“以前”“曾经”这类泛指过去的表达可以匹配未知时间；
- 有具体区间时判断是否相交；
- 事件相对时间只支持一种：“搬到某地之前”，沿真实的居住地变更版本链换算出时间区间，有歧义时不猜。

**没有的能力**：

- 时间计算，例如“两件事相隔几天”“我多久前开始的”；
- 事件排序，例如“先做 A 还是先做 B”；
- 按时长汇总。

local 模式中的时间问题（`direct_time_assertion`）只做字面匹配：原文里有“X 在什么时候”的直接断言才能回答。此外，legacy 以外的模式用的是服务端当前时间，不能指定“以某个过去时间点为准”来查询。

## 5. 弃答

这是系统的设计重心，默认保守拒答（fail closed）。分三层，详见 [recall-path.md](recall-path.md) 第 5、7 节。

**写入侧**：少写错误信息。

- 低置信度、助手推断、假设、计划、控制消息都不入库；
- 主体不明确的候选进入待澄清，不随意选一个实体；
- 未知时间保持未知，不伪造成当前时间。

**召回侧**：`src/local_recall.rs` 在以下情况下不返回事实证据：

- 问题中的指代无法绑定到具体主体（`needs_clarification`，并给出追问句）；
- 指代有歧义；
- 原文尚未整理完，或原文与记忆的链接不确定；
- 有更新的未整理原文；
- 原文中同时出现其他同类实体；
- 关系无法在字面上核对；
- 默认设置已被当前设置覆盖；
- 比较所需的两个关系缺了一个。

**答案契约**（`answer_policy`，`src/chat.rs:823`）：只有两种状态允许引用事实：

- `source_linked_fact`：值精确链接到已提交原文、在快照中唯一、没有冲突和待处理更新；
- `source_linked_exact_identity`：assisted 模式下单关系核验通过。

其余状态都给出固定的保守回复：

| 状态 | 回复方式 |
| --- | --- |
| `clarification_required` | 追问具体指谁或指什么 |
| `comparison_evidence_incomplete` | 说明缺少哪个关系的证据，无法判断 |
| `comparison_conclusion_not_verified` | 找到了记录，但不能核准比较结论 |
| `answer_not_verified` | 找到了记录，但不能核准这个回答 |
| `insufficient_evidence` | 证据不足，无法回答 |
| `unsupported_retrieval_mode` | 当前检索模式无法核准 |
| `recall_failed` | 召回运行失败，不用记忆作答 |

`memory_validate_answer` 只放行与 `safe_answer` 逐字相同的草稿。

**问题在于过度弃答**：

- 可放行的问句类型很有限：属性、费用、数量、用法、活动、默认设置等句式；
- 只做字面匹配，换一种说法就可能无法通过；
- 默认配置是 legacy 模式，这种模式对所有问题都无法核准；
- 宿主模型如果不调用校验、自行改写答案，MCP 也拦不住。

## 6. 建议的改进优先级

1. **多会话推理**：加一个“聚合查询”层，按主体、谓词、时间窗口从结构化记忆中计数、列举，并把每一项都链接到原文证据。这样聚合结果也能像单值问答一样被核准。
2. **时间推理**：在现有的时间区间表示上，补上时间差计算和事件排序。
3. **信息抽取**：扩充谓词目录，或允许按需注册新谓词，减少落到通用 `fact` 槽的内容；把证据引用精确到句子。
4. **弃答**：把默认检索模式改为 local 或 assisted；在保留原文链接校验的前提下，放宽关系匹配（例如允许经过核验的同义说法），降低过度拒答。
